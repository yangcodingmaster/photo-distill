# 手艺铁律 · Craft Rules

每一条都是某张海报翻车三次换来的。翻车的形态高度一致：**画得像了，但整张废了**。
读的时候注意每条底下的"曾经怎么错的"——那比正确做法更有信息量。

---

## A. 透视三步法

透视是照片的指纹。做每张新照片前先走一遍，这是最容易翻车的一条。

### 1. 先定地平线（＝相机眼平线）

从原片找**硬特征**：物体与地/水的**接触点**——越近的接触点在画面里越低。

案例：两个桥墩的入水点差 8px，直接判定右边是近端。
**别靠目测整图**；雾里边缘弱时自动梯度追踪也不可靠（试过，不收敛），
改用接触点/入水点这类硬特征。

量的手法：`sips -c H W --cropOffset Y X` 裁两块**等高等宽**的窗口并排比，
比在整图上目测准得多。

### 2. 地平线上下，方向相反

- 地平线**之下**的水平线（桥面、路面、岸线）：越远越**往上**收敛
- 地平线**之上**的（上层步道、屋檐、天棚）：越远越**往下**收敛

同一张海报里这两组线的斜率**必须是反的**。只做一组会立刻显假。

### 3. 斜率不是线性的，近端加速

用二次贝塞尔：远端几乎贴平地平线，近端掉得最快。
一条直斜线画不出"从深处往画面外延伸"的感觉。

### 推论（必做）

**地面线一旦变成曲线，挂在上面的一切都要脚本重算落点。**
某张重挂了塔基、两个桥墩顶、11 根吊索、16 盏灯、2 条悬链端点——
不能有任何元素还停在原来那个平的 y 上。

### 物体自身的两个角度要分开量

- `rotateY` = 正面朝哪边转（透视收敛）
- `rotateZ` = 在画框里歪多少（相机倾斜）

两个都从原片量，只做一个不够：

```css
transform: perspective(1400px) rotateY(-14deg) rotateZ(-6deg);
```

并脚本算出子元素挂点的位移。

## B. 位置与尺寸：脚本从原片映射，不凭感觉摆

十二只乌鸦的分布、三处花的坐标、层线的 y——全部从原片采样得到。
坐标保留一位小数，行尾挂溯源注释：

```xml
<path d="M 100.0,506.4 Q …" stroke-width="1.70" opacity="0.440"/>  <!-- src y=1145 -->
```

**物体可以消失，但事实不能改。** 蒸馏到最抽象的那一版，
三处空处的坐标仍然是从原片扫出来的那三个亮团中心。

## C. 材质各有语法

| 东西 | 语法 |
|---|---|
| 飘的（金光、烟） | 可以毛边 |
| 速度（行驶的车） | 必须光滑 |
| 布透光 | **换一套更亮的染料色条纹**（遮罩切换），不是叠白光——叠白光会糊成塑料反光 |
| 雾/朦胧 | **把油墨吃掉，不是涂白** |
| 凹陷/沟壑 | **层线下弯**，不要挖空 |

### 雾 = 把油墨吃掉

整组元素用同一种墨、按距离分级不透明度（近 0.5 → 远 0.06，远的再加 1.3px 模糊），
外面罩一层 SVG mask，用上/左/右/下四道 linearGradient 叠加着把墨吃掉。
**纸就是雾。白色补丁在有渐变的纸上一定露馅。**

### 凹陷 = 层线下弯

地形的下切让所有跨过它的层线在那里沉下去（左缘陡右缘缓，`depth ≈ 沟宽 × 0.06`），
场保持连续，读到的是深度。

曾三版把沟做成 mask 挖出的楔形，全部失败——楔形只有一条边在画面内时读不成形，
空白只会读作"没画完"。

> **通则：一个形状要靠"让开"来读，它的边界必须至少有两条在画面里。**

---

## D. 色块要沉在线之下

色块画在横痕组**之前**、让线从它上面压过去，它才是"地的一层"；
画在线之上就永远像贴上去的胶带。两端再用 linearGradient mask 收掉硬边。

---

## E. 全张唯一的硬边

一种整张的语法：软/无形的东西（云、雾、水汽）不画形状，
只把原片亮度场降采样成大团墨气、用 dissolve 化到没有一条边，
**全张只留一个符号有精确轮廓**。

> **自查判据：盖住那个符号，整张应该读不出任何形状。**

参数与两个坑见 [filters.md §3](filters.md)。

---

## F. 色锚要说场自己的语言

一张"全是同一种痕"的海报，色锚若做成外来的实心色带，
软边会让它像发光的塑料管，横贯全幅更是抢光整张。

改成**把那几行的痕换成红的**、与墨痕**共存**，色就融进场里了。
注意是共存不是替换——替换那一段会读作"悬在海上方的另一条带"。

---

## G. 人眼读到的边界 ≠ 亮度最陡处

实测某张雾带最陡在 y=2621，但观者认定的地平线是**痕的起点**（雾带顶 y=2256）。
色锚放在最陡处会读成"海里的一条线"。

> **边界按符号的起点定，不按物理量的极值定。**

---

## H. 只有一层标准颗粒

色块的质感只用 `grain`（feTurbulence bf .8 / numOctaves 2 / screen / opacity .12）。

任何**材质模拟**（沥青碎石、木纹、水波）都是再现，不是蒸馏。
曾叠三层骨料滤镜做柏油，像是很像，但整张就废了。

分界线：模拟"画的东西长什么样"＝再现；模拟"笔怎么走、墨怎么上纸"＝印刷语言，可以做。

---

## I. 别信几何面积，信像素统计

进成品的每个数字都要脚本算。色锚面积尤其——
几何算 2.0%，成品实测 3.18%（渗边保住了高饱和，位移还把形状撑大）。
按实测反推系数重算才落回 2.20%。

细线色锚还会被抗锯齿稀释饱和度，见 [design-system.md §3](design-system.md)。

## J. 用"纸吃掉边界"时的两个坑

浅景深的照片常常要让色块四边化回纸里（近处失焦、被遮挡、被前景吃光）。
这个手法有两个反直觉的地方，都是实测撞出来的：

**① 吃墨的渐变必须平行于它要吃的那条边。**
一条斜的上缘配一道水平的 linearGradient，只会把低的那端吃掉，
另一端原样留着一条硬直边——比不吃更难看，因为它读作"没吃干净"。
边是斜的，就把渐变的 `x1/y1→x2/y2` 设成沿该边的法线方向：

```xml
<!-- 上缘从 (425,212.5) 到 (761,241.8)，向量 (336,29.3)，法线 (-29.3,336) -->
<linearGradient id="eatT" x1="601.8" y1="200.5" x2="594.6" y2="283.0" gradientUnits="userSpaceOnUse">
```

**② 吃墨会连色锚一起吃掉。**
色锚通常在色块的某一端（天最亮的那头、光最强的那头），而那一端往往正是要被吃的边。
一次实测：上缘吃到 y=302，而高饱和区只到 y=327——色锚面积被削掉大半，
从预期的 2% 掉到 **0.84%**，贴着下限。

所以吃墨范围要**按实测的边宽定，不要凭手感放大**（那次窗框实测只有 29 画布px，
却吃了 96px）。改完必须重测色锚面积，它和吃墨范围是耦合的。

**③ 附加层必须跟主体用同一个衰减，否则它自己会切出一条边。**
颗粒层、套印错位副本这些"再画一遍"的层，默认铺满整个形状。
主体用渐变往下化开了，附加层却在 path 边界处硬切——于是横贯全幅冒出一条淡边。
一次实测：主体渐变在 y=522 归零，颗粒层却铺到 path 下缘 y=574，
在那里切出 Δ≈10/765 的亮度台阶，肉眼一眼就看见。

修法是给附加层套一个和主体同范围的 mask：

```xml
<linearGradient id="groundFade" x1="0" y1="322" x2="0" y2="522" gradientUnits="userSpaceOnUse">
  <stop offset="0" stop-color="#ffffff"/><stop offset="1" stop-color="#000000"/>
</linearGradient>
<mask id="groundM"><rect x="0" y="0" width="1400" height="933" fill="url(#groundFade)"/></mask>
...
<path d="…" filter="url(#grain)" opacity="0.10" mask="url(#groundM)" style="mix-blend-mode:screen"/>
```

**顺带一条：path 的边界要落在渐变归零之后。** 边界卡在渐变还剩 5% 的地方，
同样会留下一条线。

**横边自查**：人眼对横贯全幅的直边极敏感（马赫带），1% 的亮度差就看得见，
但脚本很容易判它"没问题"。用逐行均值的差分扫一遍，
`Δ > 8/765` 基本就是可见硬边；只在主体自己的轮廓处（比如树线上缘）才允许出现。

## 自查清单（定稿前逐条过）

- [ ] 透视：地平线定了吗？上下两组线斜率反了吗？挂件重算落点了吗？
- [ ] 观者还在数花瓣吗？（还在 = 画的仍是物体，回去继续剥）
- [ ] 盖住主符号，整张还读得出形状吗？（读得出 = 软的东西没化开）
- [ ] 色锚：脚本实测面积在 0.8–2.5%？缩略图下可见？饱和度没被稀释？
- [ ] 每条被"纸吃掉"的边，渐变方向都平行于那条边吗？吃的宽度是按实测定的吗？
- [ ] 有没有出现材质模拟？
- [ ] 每个元素有微旋转吗？有 multiply 吗？
- [ ] 这张的图形语言和此前任何一张重复吗？
- [ ] 反向约束清单逐条对过了吗？
